Project Overview

Binary optimization answers the question: given a set of options and limited resources, which combination should you choose? Each item is either included (1) or excluded (0) — no fractions, no partial choices.

This is fundamentally different from continuous optimization. There is no slope to follow, no corner point theorem. The only guarantee of optimality is examining every possible combination — or using clever strategies like branch and bound to prune the search space.

The assignment was to model a real-world selection problem using formal notation, then solve it. I built a general-purpose tool so that any binary problem can be entered, formulated, and solved — not just snack combos, but projects, equipment, courses, investments.

General Formulation

// Binary Decision Problem — General Form Sets: 𝒮 = { item₁, item₂, ..., itemₙ } // n items to consider 𝒞 = { C₁, C₂, ..., Cₘ } // m constraints Parameters: Vᵢ = objective value of item i // e.g. taste, profit Wᵢⱼ = resource j consumed by item i // e.g. cost, calories Lⱼ = limit for resource j // e.g. $15, 1200 cal Decision Variables: yᵢ ∈ { 0, 1 } ∀i ∈ 𝒮 // 1=include, 0=exclude Objective: max Z = Σᵢ∈𝒮 Vᵢ · yᵢ Subject to: Σᵢ∈𝒮 Wᵢⱼ · yᵢ ≤ Lⱼ ∀j ∈ 𝒞 // each resource limit yᵢ ∈ { 0, 1 } ∀i ∈ 𝒮 // binary constraint

Snack Combo Optimizer: You're preparing snack packs for an event. Maximize taste score while staying within Budget ≤ $15 and Calories ≤ 1,200. Each snack is either included (1) or excluded (0).

Student — Reflection Question
Was the snack with the highest taste score (Sandwich, 10) always the best choice?
Student's Own Answer
No. The Sandwich had the highest single taste score (10), but also cost $5 and 400 calories — the most expensive in both constraints. Including it forced excluding other items, resulting in a lower total. The optimal solution excluded the Sandwich and included 5 cheaper, lighter items for a combined taste of 36 vs 33.

What Did I Learn?
Dimension 01

Knowledge

  • Binary variables yᵢ ∈ {0,1} model yes/no decisions — fundamentally different from continuous variables
  • The search space grows exponentially: 6 items = 64 combinations; 20 items = 1,048,576
  • The highest individual score does not guarantee inclusion — global context matters
  • A binding constraint drives the tradeoff — relaxing it directly improves the objective
  • Formal notation (𝒮, Vᵢ, Wᵢⱼ, Lⱼ) makes any selection problem precise and solvable
  • Force-locking items reduces the search space and enables scenario analysis
Dimension 02

Skills

  • Formulating real-world decisions as formal binary optimization models
  • Implementing full enumeration: iterating all 2ⁿ bitmasks and checking feasibility
  • Building dynamic notation generators that update from live user input
  • Designing constraint utilization bars and alternative solution rankings
  • Using SUMPRODUCT formulas in spreadsheets to compute objective and constraint totals
  • Explaining why a solution is optimal — not just what it is
Dimension 03

Reflection

The most surprising result was that the Sandwich — with the highest taste score of 10 — was excluded from the optimal solution. This feels wrong until you see the numbers: including it would use $5 of the $15 budget and 400 of 1,200 calories, leaving no room for the 4 lighter items that collectively score 36 vs the Sandwich's contribution to any feasible set.


Building the general tool made me realize how universally applicable this structure is. The snack combo, project selection, and machine upgrade problems all use identical math — only the labels change. Any decision with a budget and a set of discrete options is a binary problem.


Real-world scale: Amazon uses binary selection models to decide which products to stock in fulfillment centers. Netflix decides which original content to greenlight. The same yᵢ ∈ {0,1} structure, applied to billions in decisions.
